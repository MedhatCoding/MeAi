# Medhat AI

![Medhat AI logo](assets/medhat_ai_logo.svg)

**الاسم الظاهر للتطبيق:** Medhat AI

مساعد ذكاء اصطناعي شخصي باللغة العربية، مصمم للاستخدام من الهاتف عبر المتصفح.

## العلامة التجارية وأيقونة الهاتف
- عنوان التطبيق وأيقونته داخل المتصفح مضبوطتان باسم **Medhat AI** وبشعار مخصص.
- إذا كان التطبيق مثبتًا مسبقًا على الشاشة الرئيسية، احذف الاختصار القديم ثم افتح رابط التطبيق بعد اكتمال النشر وأضفه إلى الشاشة الرئيسية مرة أخرى؛ قد يحتفظ Android/Chrome بالاسم والأيقونة القديمة في الاختصار السابق.

## الوظائف الحالية
- واجهة محادثة عربية.
- اتصال بمزود نماذج متوافق مع OpenAI Chat Completions.
- قراءة نصوص وPDF وDOCX وCSV وXLSX.
- بحث ويب تجريبي.
- ذاكرة أولية قابلة للحذف.

## النشر من الهاتف
1. اربط المستودع في Streamlit Community Cloud: https://share.streamlit.io/
2. اختر الفرع main والملف app.py.
3. في App Settings > Secrets أضف:
```toml
AI_API_KEY = "YOUR_PROVIDER_KEY"
AI_BASE_URL = "https://openrouter.ai/api/v1"
AI_MODEL = "openai/gpt-oss-20b:free"
```
4. تحقق من توافر النموذج وحدوده لدى مزود الخدمة قبل الاستخدام.

## تنبيهات
- لا تضع مفاتيح API في ملفات المستودع.
- الذاكرة المحلية قد لا تبقى بعد إعادة النشر أو إعادة تشغيل الاستضافة؛ نحتاج قاعدة بيانات دائمة مثل Supabase.
- البحث والقراءة والتحليل أدوات أولية تحتاج اختبارًا عمليًا.
- هذه نسخة MVP وليست وكيلًا مستقلًا مكافئًا لـ Manus. لا تنفذ أوامر النظام ولا تعدّل GitHub تلقائيًا حتى الآن.


## ربط الذاكرة الدائمة بـ Supabase

الكود يدعم الآن Supabase اختياريًا؛ من دون إعداداته يستمر في التخزين المحلي المؤقت.

1. أنشئ مشروعًا في Supabase وافتح SQL Editor ثم نفّذ:

```sql
create table if not exists public.memories (
  id bigint generated by default as identity primary key,
  category text not null,
  content text not null,
  created_at timestamptz not null default now()
);
alter table public.memories enable row level security;
grant select, insert, delete on public.memories to service_role;
grant usage, select on sequence public.memories_id_seq to service_role;
```

2. من إعدادات المشروع في Supabase انسخ Project URL ومفتاح Secret (أو مفتاح `service_role` القديم). المفتاح السري يجب أن يبقى في الخادم ولا يوضع في GitHub أو يشارك مع أحد.
3. في Streamlit Community Cloud افتح إعدادات التطبيق ثم Secrets وأضف:

```toml
SUPABASE_URL = "https://YOUR_PROJECT.supabase.co"
SUPABASE_SERVICE_ROLE_KEY = "YOUR_SERVER_SECRET_KEY"
```

4. أعد تشغيل التطبيق. ستظهر حالة الذاكرة الدائمة أعلى الصفحة إذا نجح الاتصال. اختبر حفظ معلومة ثم إعادة فتح التطبيق للتأكد من استمرارها.

مرجع الأمان: https://supabase.com/docs/guides/getting-started/api-keys


## مزوّدو الذكاء الاصطناعي والتبديل التلقائي

يمكن إعداد Cloudflare Workers AI للمحادثة وتوليد الصور، مع مزوّدات بديلة اختيارية. إعدادات Streamlit وواجهة Next.js مختلفة؛ استخدم أسماء المتغيرات المناسبة لكل تطبيق، ولا تفترض أن إعدادات أحدهما تُفعّل الآخر.

### إعدادات Streamlit

في Streamlit Cloud → App settings → Secrets أضف عند الحاجة:

```toml
AI_PROVIDER = "auto"
CLOUDFLARE_ACCOUNT_ID = "YOUR_ACCOUNT_ID"
CLOUDFLARE_API_TOKEN = "YOUR_WORKERS_AI_TOKEN"
CLOUDFLARE_CHAT_MODEL = "@cf/meta/llama-3.1-8b-instruct"
CLOUDFLARE_IMAGE_MODEL = "@cf/black-forest-labs/flux-1-schnell"
IMAGE_PROVIDER = "auto"
```

للمحادثة يمكن إضافة مفاتيح مزوّدات بديلة مثل `OPENROUTER_API_KEY` أو `GROQ_API_KEY` أو `CEREBRAS_API_KEY` أو `GEMINI_API_KEY`. الوضع `auto` يختار من المزوّدات المُعدّة فقط؛ لا ينشئ مفاتيح ولا يضمن توفر حصة مجانية.

### إعدادات تطبيق Next.js

أضف متغيرات البيئة في منصة استضافة الويب، ولا تضع الأسرار داخل ملفات المستودع:

- `CLOUDFLARE_ACCOUNT_ID` و`CLOUDFLARE_API_TOKEN` لتفعيل مزوّد Cloudflare للمحادثة والصور.
- أو `OPENAI_BASE_URL` و`OPENAI_API_KEY` و`OPENAI_MODEL` لمزوّد متوافق مع OpenAI Chat Completions.
- `SERPER_API_KEY` لتفعيل البحث عبر الويب والبحث المركّب.
- `MEAI_AGENT_ALLOWED_EMAILS` قائمة عناوين البريد المؤكدة المسموح لها بتنفيذ إجراءات GitHub الحساسة، مفصولة بفواصل. لا تفعّل `MEAI_AGENT_EDIT_ENABLED=true` إلا بعد ضبط هذه القائمة وتأمين حساب Supabase وGitHub token.

توضح نقطة النهاية `/api/status` الإمكانات المهيأة بحسب وجود الإعدادات؛ وجود الإعدادات لا يثبت أن الخدمة الخارجية تعمل حاليًا، ولا يعني أن تنفيذ الوكيل أو الذاكرة السحابية الدائمة مفعّلان.

## توليد الصور (اختياري)

أُضيفت صفحة **توليد الصور** داخل التطبيق. يمكن استخدام Cloudflare FLUX.1 Schnell، أو OpenAI إذا أُعدّ مفتاحه:

```toml
OPENAI_API_KEY = "YOUR_SERVER_KEY"
OPENAI_IMAGE_MODEL = "gpt-image-2"
```

المفتاح الثاني اختياري. توليد الصور عبر API خدمة مدفوعة حسب الاستخدام؛ الجودة الاقتصادية تقلل التكلفة عادةً لكنها لا تجعلها مجانية. لا تُستدعَ الخدمة إلا عند الضغط على «إنشاء الصورة». لا تضع المفاتيح في المستودع.

## حدود الإمكانات الحالية

- المحادثة والبرمجة تعملان عبر مزود النص المُعدّ في Secrets.
- البحث يحاول استخدام محركات خارجية وGoogle News RSS، وقد يفشل بسبب قيود الشبكة أو تغير المحركات؛ عند الفشل لا يعرض نتائج مختلقة.
- الذاكرة دائمة عند إعداد Supabase بنجاح؛ وإلا فالتخزين المحلي مؤقت وقد يختفي.
- توليد الصور يدعم Cloudflare Workers AI وOpenAI مع اختيار مزوّد أو fallback تلقائي؛ حصة Cloudflare محدودة، وOpenAI مدفوع.
- توليد الفيديو غير مفعّل في هذا الإصدار.
- التحكم في مواقع وحسابات خارجية غير موصول تلقائيًا؛ كل تكامل يحتاج API أو موصلًا وصلاحيات آمنة واختبارًا فعليًا.
- الوكيل يشغّل Python عند اختيار وضع التنفيذ عبر E2B Sandbox مؤقتة؛ التشغيل لا يحدث على خادم Streamlit. إنشاء ملفات مساحة العمل يتطلب موافقة منفصلة، ولا يغيّر ملفات GitHub تلقائيًا.

## حساب المستخدم والذاكرة السحابية في واجهة Next.js

أُضيف تسجيل حساب بالبريد وكلمة المرور ومزامنة يدوية منفصلة لكل مستخدم. لا تُرفع البيانات تلقائيًا؛ اضغط «حفظ في السحابة» بعد تسجيل الدخول، و«تحميل من السحابة» لاسترجاع النسخة على جهاز آخر.

1. في منصة استضافة **Next.js** اضبط متغيري البيئة:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
2. في Supabase افتح SQL Editor ونفّذ محتوى الملف `supabase/migrations/20261029_meai_cloud_memory.sql`. الجدول يستخدم Row Level Security، وكل مستخدم يستطيع قراءة وتحديث صفه فقط.
3. راجع إعدادات Authentication في Supabase، خصوصًا تأكيد البريد وسياسات كلمات المرور.
4. أعد نشر التطبيق. من «الإعدادات» أنشئ حسابًا أو سجّل الدخول، ثم احفظ البيانات يدويًا.
5. اختبر بحسابين منفصلين للتأكد من عدم ظهور بيانات أحدهما للآخر، واختبر تحميل النسخة على متصفح/جهاز آخر.

تُحفظ الجلسة في `sessionStorage` لهذا التبويب، ولا يوجد حاليًا تجديد تلقائي لرمز الدخول. قد تحتاج لتسجيل الدخول مرة أخرى بعد انتهاء الجلسة. لا تعتبر ميزة الذاكرة جاهزة إنتاجيًا قبل تطبيق الترحيل واختبار RLS فعليًا.

## آلية الوكيل الحالية

- يطلب الوكيل من النموذج اختيار الأدوات المسموح بها عند الحاجة، ثم ينفذ فقط بحث الويب للقراءة وقراءة بيانات/ملفات GitHub وتحليل الملفات المرفقة.
- يراجع الإجابة مرة واحدة ويحاول سد النواقص ضمن مهلة محدودة.
- اختيار الأدوات لا يمنح الوكيل صلاحيات shell أو التحكم العام في المواقع والحسابات. تعديل ملفات GitHub ما زال مسارًا منفصلًا، معطلًا افتراضيًا ويتطلب تأمين الوصول قبل تفعيله.
- نجاح فحوصات GitHub Actions يثبت اجتياز فحوصات الكود فقط؛ لا يثبت أن مفاتيح الاستضافة أو قاعدة Supabase أو نشر الموقع مهيأة.

## ربط Google Workspace فعليًا (Drive وCalendar للقراءة)

توجد الآن رحلة OAuth باستخدام PKCE، وتُخزّن جلسة Google في cookie مشفّر بـ AES-GCM وخصائص HttpOnly، مع تحديث access token عند توافر refresh token. الأفعال الحالية للقراءة فقط: قائمة ملفات Drive وأحداث التقويم القادمة.

1. أنشئ OAuth Client من نوع Web application في Google Cloud Console، وفعّل Google Drive API وGoogle Calendar API.
2. أضف عنوان callback التالي إلى Authorized redirect URIs في Google Cloud:
   `https://YOUR_DEPLOYMENT_HOST/api/integrations/google/callback`
3. اضبط متغيرات البيئة في استضافة Next.js:
   - `GOOGLE_CLIENT_ID`
   - `GOOGLE_CLIENT_SECRET`
   - `MEAI_GOOGLE_REDIRECT_URI` — يجب أن يطابق عنوان callback حرفيًا.
   - `NEXT_PUBLIC_SITE_URL` — أصل الموقع المنشور مثل `https://your-app.example.com`.
   - `MEAI_SESSION_SECRET` — سر عشوائي قوي لا يقل عن 32 حرفًا، ولا تضعه في Git.
4. من الإعدادات اضغط «ربط حساب Google»، وافق على النطاقات المطلوبة، ثم جرّب عرض ملفات Drive والتقويم.
5. افصل الحساب من زر «فصل Google». اختبر انتهاء الجلسة وإلغاء صلاحيات التطبيق من إعدادات حساب Google.

لا يرسل التطبيق access/refresh tokens إلى JavaScript؛ تخزّن الجلسة داخل cookie مشفّر HttpOnly. ومع ذلك، لا تُفعّل النطاقات الإضافية قبل مراجعة سياسة الخصوصية ومتطلبات شاشة الموافقة في Google Cloud.



## تشغيل الكود داخل بيئة معزولة (Streamlit)

يدعم الوكيل تشغيل كود Python تلقائيًا عبر E2B Code Interpreter. ينشئ التطبيق Sandbox سحابية مؤقتة لكل إجراء تشغيل، ولا ينفّذ الكود على خادم Streamlit أو داخل مستودع GitHub.

1. أنشئ حسابًا في [E2B](https://e2b.dev/) وأنشئ API key.
2. افتح تطبيقك في Streamlit Community Cloud ثم **App settings → Secrets** وأضف:

```toml
E2B_API_KEY = "YOUR_E2B_API_KEY"
```

3. احفظ الإعدادات وأعد تشغيل التطبيق إذا لم يلتقط السر تلقائيًا. لا تضف المفتاح إلى GitHub أو إلى ملفات المشروع أو إلى المحادثة.
4. افتح صفحة **الوكيل التنفيذي** واختر «تنفيذ وتشغيل الكود تلقائيًا». تشغيل Python يتم تلقائيًا دون موافقة منفصلة لكل تشغيل. خيار إنشاء ملفات مساحة العمل المؤقتة مستقل واختياري.

**الحدود الحالية:** Python فقط، حتى 20KB للكود، و20 ثانية لكل تشغيل، وستة إجراءات كحد أقصى لكل دورة، وتُقص المخرجات إلى 8KB. لا تُمرّر مفاتيح أو كلمات مرور أو بيانات خاصة إلى الكود. E2B خدمة خارجية وقد تسمح باتصالات إنترنت وفق إعدادات المزود؛ لذلك لا تشغّل تعليمات غير موثوقة تحتوي على أسرار.

## سياسة تعديلات الوكيل

- تشغيل الكود منفصل عن تعديل ملفات المشروع.
- لا تُعدّل أداة التنفيذ أوامر ملفات GitHub ولا تكتب إلى مساحة المشروع.
- تعديل ملف GitHub يظل معطلًا افتراضيًا، ويتطلب تفعيلًا صريحًا في إعدادات الاستضافة، وحسابًا مسموحًا، وموافقة المستخدم في الواجهة.
- إنشاء مخرجات الوكيل لا ينشرها تلقائيًا؛ النشر إلى GitHub يتطلب إجراءً منفصلًا وتأكيدًا صريحًا.
